<h1>Consistency Makes Coding Easier</h1>

<p>
    Learning how to code as a new developer can be a struggle, especially when learning it through college classes. One of the main reasons for this is that the requirements can be different every time. You might have to use a different programming language, a different coding style, or even a completely different way of doing things. One assignment might have you writing a small script, while another has you working on a larger project or using a coding website. Because of this, learning how to code is not always just about learning how to program. You also have to learn how that specific class or assignment wants you to program.
</p>

<h2>Every Project Can Feel Different</h2>

<p>
    I think this is one of the more difficult parts of being a new developer. When I think about software engineers working in the industry, I imagine that they usually stay within the same general environment for a while. They might work with the same programming language, tools, and coding standards for a project. This lets them get used to how everything is organized instead of having to learn a completely different way of doing things every time.
</p>

<p>
    Classes can be different. The requirements can change every semester or even every assignment. One class might use one programming language while another uses something completely different. Even if two assignments use the same language, they can still have different requirements for how the code should be written. This means I sometimes have to spend time figuring out not only how to solve the problem, but also how the professor wants me to write the solution.
</p>

<p>
    This is one reason I think coding standards are useful. They give you some consistency in an area of programming where there can otherwise be a lot of different ways to do things.
</p>

<h2>Consistency Makes Coding Easier</h2>

<p>
    When I think about coding standards, I do not only think about things like indentation or whitespace. Those are definitely part of it, but coding standards can also include things like naming variables, organizing functions, and how certain problems should be handled.
</p>

<p>
    The main benefit I see from coding standards is consistency. If I write my code in a consistent way, I do not have to constantly think about how I should format everything. I can focus more on actually solving the problem instead of thinking about where a space should go or how I should organize something.
</p>

<p>
    This is one reason I have found ESLint useful. Instead of having to remember every small formatting rule myself, ESLint can point out problems for me. Things like whitespace, unused variables, and other errors can be detected automatically. This makes those things less of a thought while I am coding. I can just write my code and let ESLint point out something that needs to be fixed.
</p>

<p>
    I also think this makes it easier to use older code as a reference. If I have already written something using the same standards, I can look back at it when working on something new. I do not have to figure everything out from scratch. I can use my previous work as an example and build from it.
</p>
